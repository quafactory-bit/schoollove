# 작업지시서 — Threads 실시간 답글 도우미 (승인형)

작성 2026-10-15 · 대상: 개발 에이전트(GPT·Codex·Claude Code) · 목표 가동 2026-10-26 · 운영자 승인 후 배포
저장소 루트 `AGENTS.md`의 규칙(Git, 환경변수, 원격 변경 승인, 최종 보고 형식)을 그대로 따른다.

## 1. 왜 하는가
- 10/19부터 Threads @schoollove_kr을 하루 7개 글로 운영하고, 댓글에는 15분 안에 답하는 게 목표다(`sns-ops/playbook/daily-routine.md`).
- 운영자는 떡볶이집을 하면서 운영한다. 앱 알림을 계속 보고 답을 타이핑하기 어렵다.
- 그래서 **댓글이 달리면 AI가 답글 초안을 만들어 폰(텔레그램)으로 보내고, 운영자가 버튼 하나로 승인하면 답글이 달리게** 한다.
- 사람이 승인하지 않은 글·답글은 절대 올라가지 않는다. 이것이 이 도구의 핵심 규칙이다.

## 2. 범위
| 단계 | 내용 | 필수 |
|---|---|---|
| 1 | 내 글에 달린 댓글·멘션 → 답글 초안 → 텔레그램 [승인][수정][건너뛰기] → 승인 시 답글 게시 | 필수 |
| 2 | 키워드로 남의 글 후보를 찾아 초안과 함께 텔레그램으로 보내기 (**게시는 하지 않는다** — 운영자가 앱에서 직접 단다) | 필수 |
| 3 | 매일 22:30 KST 텔레그램 요약: 받은 댓글 수, 승인·수정·건너뜀 수, 평균 응답 시간 | 선택 |

**하지 않는 것:** 승인 없는 게시, 좋아요·팔로우·리포스트, DM, 남의 글에 자동 답글, Instagram.

## 3. 운영자가 미리 준비하는 것 (값은 채팅에 붙이지 않고 Vercel 환경변수 화면에 직접 넣는다)
- 메타 개발자 앱: 사용 사례 "Threads API 액세스", @schoollove_kr을 Threads 테스터로 등록·수락
- 권한: `threads_basic`, `threads_content_publish`, `threads_read_replies`, `threads_manage_replies`, `threads_manage_mentions`, `threads_keyword_search` (필요하면 `threads_manage_insights`)
- Threads 장기 접근 토큰, 앱 시크릿
- 텔레그램 봇 토큰(BotFather), 운영자 개인 chat_id
- Claude API 키(console.anthropic.com — 구독과 별도인 사용량 과금. 답글 초안 수만큼만 든다)
- 필요한 환경변수 **이름 목록**은 개발 에이전트가 먼저 알려 준다. 키 값은 운영자만 넣는다.

## 4. 구조
- **사이트 코드와 분리한다.** 별도 Vercel 프로젝트(또는 저장소 안 별도 폴더 + 별도 Vercel 프로젝트)로 만들어, 회원 서비스의 환경변수·DB와 섞이지 않게 한다.
- **저장소:** 처리한 댓글 ID, 상태(대기·승인·수정·건너뜀·실패), 초안, 게시된 답글 ID, 시각만 저장한다. **회원 DB(schoollovei)는 쓰지 않는다.** 작은 별도 저장소(Upstash·Vercel KV·별도 Supabase 프로젝트 등) 중 무료로 되는 것을 고르고 이유를 보고한다. 30일 지난 기록은 지운다.
- **끝점(엔드포인트)**
  - `/api/threads/webhook` — 메타 웹훅 검증(GET challenge)과 수신(POST). 메타 서명(`X-Hub-Signature-256`, 앱 시크릿)이 맞지 않으면 버린다.
  - `/api/telegram/webhook` — 텔레그램 버튼·답장 수신. `setWebhook`의 `secret_token` 헤더와 **운영자 chat_id**가 모두 맞을 때만 처리한다.
  - `/api/cron/keyword` — 2단계 후보 찾기.
  - `/api/cron/refresh-token` — Threads 장기 토큰 갱신(주 1회). 실패하거나 만료 7일 전이면 텔레그램으로 알린다.

## 5. 1단계 흐름 — 내 글 댓글
1. 웹훅으로 새 답글·멘션 이벤트를 받는다. 같은 ID는 한 번만 처리한다(중복 이벤트 대비).
2. 내 계정이 쓴 답글, 이미 처리한 답글은 무시한다.
3. API로 댓글 본문과 원글 본문을 가져온다.
4. **민감 판정 먼저:** 아래 "운영자 직접" 조건에 걸리면 초안을 만들지 않고 텔레그램에 "직접 확인 필요"로만 보낸다.
5. Claude API로 초안 1개를 만든다(7절 규칙). 초안이 규칙을 어기면(링크 포함, 300자 초과 등) 한 번 다시 만들고, 그래도 어기면 "직접 확인 필요"로 보낸다.
6. 텔레그램 메시지: 원글 첫 줄, 댓글 전문, 초안, 버튼 `[승인] [수정] [건너뛰기]`, 댓글로 가는 링크.
7. **[승인]** → Threads API로 그 댓글에 답글을 단다(컨테이너 생성 → 게시 2단계). 결과(성공·실패)를 같은 텔레그램 메시지에 표시한다.
   **[수정]** → 운영자가 그 메시지에 답장으로 고친 문장을 보내면 그 문장으로 게시한다. 게시 전에 "이대로 올릴까요? [올리기] [취소]"를 한 번 더 묻는다.
   **[건너뛰기]** → 아무것도 올리지 않고 기록만 남긴다.
8. 실패하면 이유를 텔레그램으로 알리고 다시 시도 버튼을 준다. 자동 재시도는 1회까지.

## 6. 2단계 흐름 — 남의 글 후보
- 키워드: `동창`, `초등학교 친구`, `학창시절`, `졸업`, `연락 끊긴 친구`, `1인 창업`, `자영업`, `바이브코딩`, `AI로 만든`.
- 최근 3시간 글만, 내 계정 글·이미 보낸 글 제외, 실행 1회에 최대 5개를 초안과 함께 보낸다. **게시 버튼은 없다.** 텔레그램 메시지에는 원글 링크와 초안만 있다.
- 키워드 검색은 쿼리 한도가 있다. 현재 공식 한도를 확인하고, 한도의 절반 이하만 쓰도록 실행 간격을 정해 보고한다(기본 60분, 07~23시만).
- Vercel 요금제의 크론 빈도 제한도 확인한다. 1시간 간격이 안 되면 대안(GitHub Actions 스케줄 등)을 제안만 한다.

## 7. 답글 초안 규칙 (Claude API 시스템 프롬프트에 그대로 넣는다)
- 화자: 떡볶이집을 하면서 AI로 스쿨러브아이를 만든 사람. 1인칭 편한 반말. 개발 용어 대신 쉬운 말.
- 1~3문장, 200자 안팎(최대 300자). 질문으로 끝내서 대화를 잇는다. 같은 문장·이모지를 반복하지 않는다.
- **링크·주소를 넣지 않는다.** 서비스 주소를 물으면 "프로필에 있어!"라고만 한다.
- 서비스 설명은 아래 범위에서만 한다(`sns-ops/content/approved-claims.md`).
  - 학교 + 졸업연도 + 정확한 이름이 맞을 때만 찾을 수 있다.
  - 수락 전에는 안부 한 번만 보낼 수 있다. 둘 다 수락해야 연결되고, 그때 상대가 허용한 인스타 주소만 보인다. 몰래 보는 건 없다.
  - 우리 학교 명단은 같은 학교를 등록하고 명단 표시를 켠 동창끼리만 보이고, 언제든 끌 수 있다. 로그인 안 한 사람·검색엔진에는 안 보인다.
  - Google 계정으로 시작한다. 만 19세 이상만 쓸 수 있다.
- **쓰면 안 되는 말:** 이름만·초성으로 찾을 수 있다, 몰래 볼 수 있다, 자유롭게 메시지를 주고받는다, 실명 인증된 사람만 있다, 가입자 수·학교별 인원·성공 사례 같은 숫자나 후기, 학생도 쓸 수 있다.
- 보안 질문("AI로 만들었는데 괜찮아?"): 위 범위의 사실만 말하고 "구조 세부는 보안상 공개 안 하는 거 이해해줘"로 끝낸다.
- 가게 위치·이름: "가게는 아직 비밀로 할게 ㅋㅋ".
- 이름 추천 댓글: 고맙다고 하고 "모아서 나중에 투표해볼게". (`sns-ops/content/name-ideas.md`에 기록할 수 있게 텔레그램 메시지에 "이름 추천" 표시를 붙인다.)
- 실명을 쓰게 유도하지 않는다("이름은 안 적어도 돼").
- **운영자 직접 (초안 만들지 않음):** 욕설·혐오·분쟁, 실명·학교·연락처 같은 개인정보가 담긴 댓글, 미성년자로 보이는 댓글, 자해·위기·건강 같은 민감한 이야기, 법률·환불·탈퇴·개인정보 삭제 요청, 언론·제휴 문의, 무슨 뜻인지 모르겠는 댓글.

## 8. 보안·개인정보
- 비밀값은 환경변수에만 둔다. 로그에 토큰·키·댓글 전문을 남기지 않는다(댓글은 ID와 앞 20자까지만).
- 텔레그램은 운영자 chat_id 한 명만 처리한다. 다른 사람이 봇에 말을 걸면 무시한다.
- 승인 없는 게시 경로가 코드에 없어야 한다. 테스트로 확인한다.
- Threads API 한도(하루 게시 250개, 답글 1,000개)를 넘지 않게 하루 답글 상한을 100개로 둔다.

## 9. 확인 방법
1. 단위 테스트: 서명 검증 실패 시 거부, 중복 이벤트 1회 처리, chat_id 불일치 무시, 초안 규칙 검사(링크·길이·금지 문구), "운영자 직접" 판정.
2. 통합 테스트(운영자와 함께): 테스트용 글을 하나 올리고 운영자가 다른 계정으로 댓글 → 1분 안에 텔레그램 도착 → [승인] → 답글 게시 확인 → [수정]·[건너뛰기]도 한 번씩.
3. 토큰 갱신을 수동으로 한 번 실행해 성공 알림 확인.
4. 2단계: 키워드 실행 1회 → 후보 5개 이하, 게시 버튼 없음 확인.

## 10. 하지 말 것
- 승인 없이 게시·답글·좋아요·팔로우 하지 않는다. 남의 글에 답글을 다는 기능을 만들지 않는다.
- 회원 서비스(사이트) 코드·DB·환경변수를 바꾸지 않는다.
- `.env` 값을 출력하거나 커밋하지 않는다.
- 운영자 승인 전에 배포하지 않는다.

## 12. 진행 기록 (2026-10-19, Claude)
- 만든 곳: 저장소 `reply-helper/` (사이트와 분리, 외부 패키지 없는 순수 JS — 사이트 tsc·vitest·build에 안 잡힘 확인). 상태 `CODE_PRESENT` · `LOCAL_VERIFIED`(테스트 34개).
- 바뀐 점: 메타 웹훅은 라이브 모드·비즈니스 인증·고급 액세스가 있어야 남의 댓글 알림이 와서, 1단계는 **5분마다 확인**(Upstash QStash 스케줄, 07:00~22:55 KST)으로 했다. 웹훅 경로는 나중용으로 남김.
- 2단계 키워드 후보: `threads_keyword_search` 승인 전엔 내 글만 검색됨 → 기본 꺼짐(`KEYWORD_SEARCH_ENABLED`).
- 저장소: Upstash Redis 무료(새 DB). 환경변수 이름·설정 순서·한계·비용은 `reply-helper/README.md`.
- 남은 것: 운영자 준비(토큰·봇·API 키·Upstash) → Vercel 별도 프로젝트 배포·환경변수 → `/api/setup` 점검 → 통합 테스트. commit·push·배포는 운영자 승인 후.

## 승인 요청 1 — 별도 일별 집계 표1개 (SQL이 아닌 초안)

기존표를 억지로 바꾸려면 event/source check와 기본키/호출 계약을 손대야 한다. 기존표·기존migration·기존숫자는 보존하고 지시서5절③에 해당하는 `part2_daily_funnel`1개와 새 service-only 기록/조회 함수만 추가하는 안을 추천한다. 추가 전용 migration은 승인 후 CLI로 생성한다. 기존함수의 DROP·RENAME·본문 교체나 사용자 행 변경은 하지 않는다.

| 열 초안 | 의미 | 제한 |
|---|---|---|
| metric_date | 한국시간 날짜 | 시각을 저장하지 않음 |
| event_key | 고정 단계 코드 | 허용된 코드만 |
| source_channel | direct/instagram/threads/share/other | ref=ig는instagram으로정규화, 임의 query/referrer 원문 금지 |
| browser_context | external/instagram/threads/facebook/unknown | UA에서 분류만, UA 원문 저장 금지 |
| school_id | 공개 학교 식별자 또는NULL | public.schools의 학교만, 학교 통계에만 사용. 회원 식별자가 아님 |
| event_count | 해당 조합의 합계 | 양수 정수, 같은 조합은 단일 원자적UPSERT로+1 |

- 고유 조합: 날짜+event+source+browser+school. 학교NULL도 같은 조합으로 취급한다. 실제 PostgreSQL 버전과 지원 여부는 구현 전에 확인한다.
- 넣지 않는 것: 일련번호, 개별 이벤트 행, 사용자/세션/기기 ID·해시, 이메일·이름·초성·한마디·졸업연도, IP·UA·검색어·전체URL·referrer 원문, 계정과의 연결.
- 기존 public_account_daily_funnel과 signup_attribution은 계속 원래 용도로 유지한다. 과거 자료를 역추정/backfill하지 않는다.
- RLS로 브라우저역할의 표 읽기·쓰기와 기록RPC 실행을 차단한다. 서버가 허용 목록/학교 존재를 검증하고 기존 요청제한 경계를 사용한다. 지표저장 실패가 검색·로그인·가입을 실패시키지 않는다.
- 관리자 표와 funnel_feedback_report.json은 관리자 검증을 모두 통과한 뒤 제공하고 no-store로 반환한다. 정적 public/ 파일이나 누구나 접근하는 JSON URL을 만들지 않는다.

### 이벤트 정의 초안

1. landing_view: 실제 진입 화면1회. ref/기존 유입코드와 브라우저 분류만 사용한다.
2. school_search_submitted: 검색 실행 횟수. 검색어 원문은 보내지 않는다.
3. school_result_selected: 검색 결과의 특정학교 선택 횟수. 공개school_id만 사용한다.
4. school_detail_viewed: 해당 학교 상세 진입.
5. chalkboard_initials_started: 초성 입력 시작 여부만. 입력 원문은 수집하지 않는다.
6. google_login_started: 고정Google 시작 경계에서 실제 인증 이동을 허용한 횟수. 단순 버튼 노출은 제외한다.
7. google_login_completed: 기존 세션 완료 경계가 성공한 횟수. 브로커 내부 변경이 필요하면6C에 따라 다시 멈춰 묻는다.
8. signup_completed: 성인·필수동의·프로필·첫 학교 등록까지 끝난 최초 완료. 프로필만 만든 경우를 출석 완료로 오인하지 않는다. 기존 최초 완료 경계를 재사용한다.
9. summons_share_clicked / cohort_link_share_clicked: 공유 버튼 클릭. 실제 외부 게시/상대 열람으로 해석하지 않는다.

학교별 관심은 검색결과에서 그 학교를 **선택한 횟수**로 정의하는 안이다. 검색어를 저장하거나 결과에 뜬 모든학교를 각각 검색1회로 세지 않는다. 운영자가 “학교별 검색 수”를 다른 뜻으로 원하면 구현 전에 정의를 확정한다.

활동은 사람 수가 아닌 횟수, 최초 가입은 기존 milestone 기준이다. 익명 표에 개인키를 넣어 전 단계의 같은 사람을 추적하거나 완전한 개인별 전환율을 계산하지 않는다. 인증 완료와 가입 완료는 별도로 표시한다. 뒤 단계에서 아직 구현되지 않은 초성/소환장 이벤트는 “미계측”으로 표시하며 실제0건과 섞지 않는다.

### 관리자 표/JSON 초안

- 최근7일/14일, 한국시간 집계. 기간의 날짜 경계와 조회 시점을 명시한다.
- 모든 출력 표·JSON에서10미만 칸은 마스킹한다. 비율의 분자/분모가 가려지면 비율도 가린다. 합계/다른칸으로 역산 가능하면 관련값도 함께 가린다.
- 홈→검색35%, 상세→로그인20%, 가입→공유15% 미만은 표본/계측이 충분한 경우 문구A/B 후보 설명으로만 출력한다. 자동 교체하지 않는다.
- 0건/가림/아직 미계측/조회실패를 구별하고 오류·미계측을0으로 만들지 않는다. 기존관리자 로그인/권한/삭제 경계는 변경하지 않는다.

## 승인 요청 2 — “가입0명 학교”와10미만 가림

지시서는 “검색은 많은데 가입0명인 학교 상위10개”와 “10명미만 칸은 기존처럼 가림”을 동시에 요구한다. 목록 제목만으로도 해당학교 가입자가 정확히0명임을 드러내므로 칸의숫자만가려서는 후자를 충족하기 어렵다.

추천: **검색결과 선택10회 이상, 가입10명미만인 학교 상위10개**로 표시하고 가입숫자/전환율은 가린다. 0명과1~9명 학교를 구분해서 내보내지 않는다. 이 정의 변경도 운영자 승인 전에는 구현하지 않는다. “정확히0명” 목록을 꼭 유지하려면 그 집계 공개 예외를 별도로 결정해야 한다.

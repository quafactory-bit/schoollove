## P2 범위 (구현 보류 이유)
- 신규 Google 계정은 DB 함수 `record_verified_social_identity_from_upstream_leg`가 `RECOVERY_REQUIRED`를 돌려주고, 복구 OTP 소비(`consumeRecoveryAndDecide`) 뒤에만 계정이 결정된다.
- 재로그인(`BOUND_PROVISIONAL_REAUTH_READY`), 활성화, 브로커 코드 발급 함수가 모두 `recovery_email_verified_at`·암호문 열이 채워진 계정만 정상으로 본다. "나중에 등록"을 넣으려면 최소 다음을 함께 바꿔야 한다:
  1. 신규 신원 → 복구 없이 provisional 계정 결정하는 새 경로(중복 계정 판정 기준 재정의 포함)
  2. 재로그인·활성화·발급 함수의 계정 성립 조건(복구 열 NULL 허용) — 기존 함수 교체(CREATE OR REPLACE)라 "추가만" 원칙의 예외 승인 필요
  3. 계정 설정의 "복구 이메일 나중에 등록" 화면과 OTP 연결
  4. 결정 문서(`docs/decisions`) + Preview 새 Google 계정 실가입·재로그인·탈퇴 검증
- One Tap은 Google ID 토큰으로 위 브로커에 들어오는 새 진입점이 필요하고, Google Cloud 콘솔의 승인된 JavaScript 원본 등록과 공개 클라이언트 ID 환경변수(건별 승인)가 필요하다. 인앱 브라우저에서 실패하면 지금의 Google 버튼·외부 브라우저 안내로 돌아가게 만든다.
- 잘못되면 **운영 로그인이 막히거나 중복 계정이 생길 수 있는** 부분이라, 설계 문서 → 승인 → 구현 → Preview 실가입 검증 순서의 별도 작업으로 진행하는 것을 제안한다.

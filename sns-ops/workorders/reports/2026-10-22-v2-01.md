### 래퍼 함수 구조
- `search_schools_with_activity`는 `20260803120000_public_account_soft_launch.sql`(601행)에만 정의돼 있다.
  - 반환 형식을 `TABLE(id uuid, school_name text, school_type text, sido text, sigungu text, slug text, address text, school_code text, created_at timestamptz)`로 **고정 선언**하고,
  - 통계 함수 호출 뒤 `RETURN QUERY SELECT * FROM public.search_schools_v2(q,lim)`로 결과를 그대로 넘긴다.
- **`search_schools_v2`는 저장소의 어떤 migration에도 정의가 없다.** 운영 DB에 예전에 직접 만든 함수이고(`scripts/phase10l/postgrest-test-bootstrap.sql` 주석: "historical SQL predates repository migrations"), 로컬 테스트는 반환 형식을 text로 가정한 대체 함수를 쓴다.

### 추정 원인 (작성 당시 — 아래 "Preview 확인 결과"에서 1번으로 확정)
1. **가장 유력:** 운영 `search_schools_v2`의 실제 반환 컬럼 개수·타입(예: `varchar`, 추가 컬럼)이 래퍼가 선언한 9개 text 형식과 다르다. 이 경우 `RETURN QUERY`가 "structure of query does not match function result type"(42804)로 실패하고 PostgREST가 400을 준다. 자동완성은 `search_schools_v2`를 직접 불러서 정상인 현상과 맞는다. 로컬 테스트는 같은 형식의 대체 함수를 써서 이 차이를 못 잡는다.
2. 그 다음: 통계 기록 `increment_public_account_metric`의 INSERT가 실패(제약·권한). 저장소 기준 `event_key`·`source_channel` 값은 CHECK 목록 안이라 가능성은 낮다.

### 운영자가 확인할 수 있는 읽기 전용 SQL (Supabase SQL Editor, 데이터 변경 없음)
```sql
select pg_get_function_result('public.search_schools_v2(text,integer)'::regprocedure);
select pg_get_function_result('public.search_schools_with_activity(text,integer)'::regprocedure);
```
두 결과가 컬럼 이름·타입까지 같지 않으면 원인 1이 확정이다.

## Preview 확인 결과 (2026-10-23)
- Preview Supabase 프로젝트 `schoollove-preview`가 무료 요금제 비활동으로 **일시정지** 상태였다. 이 때문에 처음 Preview 사이트에서는 자동완성·학교 페이지가 모두 실패했다. 운영자가 대시보드에서 직접 재개(Resume)했다. 에이전트는 재개·설정 변경을 하지 않았다.
- 재개 후 운영자 브라우저의 SQL Editor에서 **SELECT만** 두 번 실행했다(데이터·함수·권한 변경 없음).
  1. 함수 카탈로그와 학교 수:
     - `search_schools_v2(text,integer)` 반환 `SETOF schools`
     - `search_schools_with_activity(text,integer)` 반환 `TABLE(id uuid, school_name text, school_type text, sido text, sigungu text, slug text, address text, school_code text, created_at timestamptz)`
     - `school_year_counts_v2`는 없음(04번 migration 미적용, 정상)
     - 학교 1곳(`high` 1, 진명여자고등학교)
  2. `information_schema.columns` 기준 `public.schools` 컬럼 12개: `id, school_name, school_type, sido, sigungu, address, school_code, slug, created_at, search_blob, current_level, level_updated_at`
- **원인 확정(Preview 기준):** 래퍼는 9개 컬럼(`slug`가 `address`보다 앞)을 선언했는데, `search_schools_v2`는 schools 행 전체(12개, `address`가 `slug`보다 앞)를 돌려준다. `RETURN QUERY SELECT *`가 형식 불일치로 매번 실패한다. 08-03 래퍼 작성 이후 schools에 `search_blob`·`current_level`·`level_updated_at`이 있는 한 항상 실패하는 구조다.
- Preview 사이트(`v2-simplified` 배포, 375px)에서 확인:
  - 자동완성 "진명" → 진명여자고등학교 표시.
  - "학교 검색" 버튼 → 브라우저 콘솔에 `search_schools_with_activity failed; falling back to search_schools_v2` 경고 1줄(검색어 없음), 화면에 "'진명' 검색 결과 1건". **v2-01 폴백이 실제로 동작.**
  - 학교 페이지·연도 페이지는 새 화면으로 열림(연도별 수는 04번 migration 미적용이라 "잠시 불러오지 못했어요" — 예상대로).

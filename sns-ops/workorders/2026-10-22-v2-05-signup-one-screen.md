# 작업지시서 v2-05 — 가입을 한 화면으로

마스터 규칙 적용 · 예상 3~4시간 · 모델: **Opus 이상** · 선행: 02·03·04 · 기준 화면: 목업 2번 · **인증을 건드리므로 Preview에서 먼저 확인**

## 1. 왜
- 로그인 없을 때 27명이 등록했고, 로그인을 넣은 뒤 등록이 멈췄다. 로그인은 못 빼므로 그 뒤의 마찰을 전부 뺀다.
- 지금 흐름: Google → 복구 이메일 확인(조건부) → 온보딩 → 환영 안내 4단계 → 학교 등록 → 명단 표시 선택. 목표 흐름: **Google → 한 화면(학교·졸업연도·체크 3개) → 출석부.**

## 2. 흐름
1. `/login`: 버튼 하나 `Google로 계속하기`. 설명 2줄만: `친구의 인스타그램 주소가 궁금하다면 Google로 시작해요. 만 19세 이상만 쓸 수 있어요.` 현재의 긴 고지문은 `개인정보처리방침` 링크로 대체(법적 고지는 약관·방침 페이지에 유지).
2. `/auth/social/complete`: 성공 시 **바로** `/onboarding`으로. 복구 이메일 확인 단계는 "필요한 경우에만"이었으므로 **기본 흐름에서 제거**하고, 계정 설정(`/account/safety`)에서 나중에 할 수 있게 둔다(기존 API 유지).
3. `/onboarding` → 한 화면(목업 2번):
   - 진행 바 3칸(2/3)
   - 학교(자동완성, 기존 `SearchBar` 재사용) · 졸업연도(02번 범위) · 반(**선택**, 접힌 상태)
   - 체크 3개: `만 19세 이상 본인이에요` / `이름·졸업연도가 같은 학교 회원에게 보여요. 언제든 숨길 수 있어요.` / `이용약관 · 개인정보처리방침 동의`
   - 버튼 `등록하고 출석부 보기`
   - 이름: Google 프로필 이름을 자동 등록하지 않는다는 현재 원칙 유지 → 이름 입력칸 1개를 학교 위에 둔다(`출석부에 보일 이름`, 실명 권장 문구).
   - 제출 = 기존 API 조합: 동의 기록(`record_own_required_consents`) → 프로필 upsert → 학교 등록(`add_own_school_membership`) → **명단 표시 플래그 = true** (두 번째 체크가 곧 동의). 한 트랜잭션처럼 보이게 하되, 뒤 단계가 실패하면 앞 단계 결과를 유지하고 에러를 보여준다(재시도 가능).
4. 완료 → 08번의 "홈 화면에 추가" 화면 → `/account`(출석부). 08번 전까지는 바로 `/account`.
5. 제거(화면에서만): `components/account/*WelcomeGuide*`, 온보딩 다단계, 명단 표시 선택 화면, `PrivacyTransitionNotice`(이미 전환 끝남), `RegistrationSuccessFeedback`의 LEVEL_UP/IMMINENT 모드(NORMAL만 남기고 문구는 `출석부에 등록됐어요`).

## 3. 데이터 호환 (되돌리기 보장)
- 새 테이블·컬럼 없음. 명단 표시는 **기존 플래그 컬럼**에 쓴다. v1 코드로 되돌려도 v2 가입자가 명단 표시 켜진 상태로 보인다.
- 동의 버전 문자열은 새 값(`v2-2026-10-22`)으로 기록해 나중에 구분 가능하게.

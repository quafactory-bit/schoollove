# 작업지시서 v2-02 — 졸업연도 규칙 (미성년자 구조적 차단)

마스터 규칙 적용 · 예상 1시간 · 모델: Sonnet/Opus · 선행: 00

## 1. 왜
- 19세 체크박스는 거짓말을 막지 못한다. 졸업연도로 **재학 중인 학교 등록 자체를 불가능하게** 만든다. 지금 고등학생은 자기 학교를 등록할 수 없다.
- PASS 본인인증은 넣지 않는다(건당 비용, 전환율 하락).

## 2. 규칙
학교 유형별 허용 졸업연도 상한 (`Asia/Seoul` 기준 올해 = Y):
- 고등학교: `≤ Y − 1`
- 중학교: `≤ Y − 4`
- 초등학교: `≤ Y − 7`
- 대학교: `≤ Y` (허용, 입학연도 입력 시에도 동일 로직은 적용하지 않음 — 대학은 성인 전제)
- 하한: `≥ 1950`
- 2026년 기준: 고 ≤ 2025, 중 ≤ 2022, 초 ≤ 2019.

## 3. 작업
1. `lib/policy/adultEligibility.ts`(또는 가장 가까운 정책 파일)에 `graduationYearRange(schoolType, now)` 순수 함수 추가 + 테스트(경계값 각 유형 3개씩).
2. 학교 등록 입력(졸업연도 select)에서 이 범위만 선택지로 보여준다. 범위 밖 값을 보낸 요청은 서버 API(`/api/account/memberships`)에서 거부(400, 메시지 "재학 중인 학교는 등록할 수 없어요").
3. 안내 문구(목업 2번 화면): "고등학교는 2025년 이하 졸업연도만 고를 수 있어요. 재학 중인 학교는 등록할 수 없어요." — 유형·연도는 계산값으로.
4. DB: **새 migration 파일**로 `add_own_school_membership` RPC 안에 같은 검증을 추가하는 새 버전 함수(`CREATE OR REPLACE`가 아니라 기존 migration은 손대지 않고 새 파일에서 `CREATE OR REPLACE FUNCTION`). 원격 적용은 승인 대기로 보고.
5. 검증 순서대로. 커밋 `v2-02: graduation-year range rule blocks current students`.

## 4. 하지 않는 것
- 기존 등록 데이터 수정 금지(규칙은 신규 등록에만).
- 19세 체크박스 제거 금지(둘 다 둔다).

## 5. 완료 조건

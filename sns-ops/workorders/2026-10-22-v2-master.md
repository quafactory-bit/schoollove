## 2. 공통 규칙 (모든 지시서에 적용)
1. **`AGENTS.md`를 먼저 읽는다.** 00번에서 개정한 뒤의 `AGENTS.md`가 기준이다. 개정 전 B·C·G·E절은 "v1 보류"이며 v2 작업에 적용하지 않는다.
2. **브랜치:** 모든 v2 작업은 `v2-simplified` 브랜치에서 한다. `main`과 `v1-keep`은 건드리지 않는다.
3. **사전 승인:** 운영자는 이 마스터 지시서를 건네는 것으로 `v2-simplified` 브랜치 안에서의 **commit**을 사전 승인한다(지시서 번호별로 1커밋 이상, 메시지 앞에 `v2-NN:`). **push·merge·production 배포·Vercel/환경변수 변경·Supabase 원격 migration·원격 DB mutation은 여전히 건별 승인**이다(`AGENTS.md` O절).
4. **되돌리기 보장 — 금지 3가지:** ① 테이블·컬럼 DROP 또는 RENAME ② 사용자 데이터(profiles·memberships·connections·초기 등록 27건 포함) 삭제·수정 ③ 기존 migration 파일 수정. 마이그레이션은 **추가만**(새 파일, 새 함수, 새 컬럼 nullable). 빼는 기능은 **화면·라우트에서만 내리고** 코드 파일은 삭제하지 않는다(`v1/` 접두 폴더로 옮기는 것은 허용).
5. **신규 테이블 0 원칙:** v2의 명단·요청·수락 상태는 기존 테이블·컬럼(명단 표시 플래그, connections)에 쓴다. v1 코드로 되돌려도 v2 가입자가 보여야 한다.
6. **production 파일명 덮어쓰기 금지:** 승인 전에는 이미지·폰트 등 정적 자산을 같은 이름으로 덮어쓰지 않고 `-v2` 접미사로 추가한다.
7. **검증 순서는 `AGENTS.md` L절 그대로:** 관련 테스트 → `npm run typecheck` → `npm test` → `npm run build` → `git diff` 검토. 실행 안 한 검증을 통과했다고 쓰지 않는다.
8. **테스트 정리 원칙(L절 보완):** 화면에서 내린 기능(XP·레벨·순위·안부·환영 안내)의 테스트는 "약화"가 아니라 **그 기능과 함께 `v1/`로 이동**한다. 남는 기능의 테스트는 지우거나 약화하지 않는다.
9. **보고:** 각 지시서가 끝나면 `sns-ops/workorders/reports/2026-10-22-v2-NN.md`에 `AGENTS.md` P절 형식으로 쓴다. 맨 끝에 "SNS 일지용 한 줄"(형식: 한 일 | 막힌 것이나 고민한 것 | 결정한 것, 보안 세부·키·개인정보 제외, 개발 모르는 사람도 이해되게). 한 차수가 끝나면 `reports/2026-10-22-v2-round-N.md`에 차수 요약(변경 파일 전체, 남은 위험, 승인 필요 항목)을 쓴다.
10. **비밀값:** 키·토큰·환경변수 값을 코드·보고·커밋 메시지에 쓰지 않는다. 환경변수는 **이름만** 보고한다.
11. **한국어 인코딩:** 한국어가 들어간 파일은 UTF-8(BOM 없음), LF. PowerShell `Set-Content` 금지.
12. **디자인 기준:** 색·간격·문구는 `artifacts/mockups/2026-10-22-v3-sns-app/schoollove-v3.html`의 CSS 변수와 화면을 따른다. 브랜드색 `#0f7b5f`, 배경 흰색, 글자 `#0a0a0a`. 이름은 아직 "스쿨러브아이"를 쓰되, 화면 문구에서 "명단"은 "출석부"로 쓴다(10번에서 이름이 바뀌면 그때 일괄 치환).

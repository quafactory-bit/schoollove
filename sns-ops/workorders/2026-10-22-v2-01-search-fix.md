# 작업지시서 v2-01 — 학교 검색 버튼 에러 수정

마스터 규칙 적용 · 예상 30분 · 모델: Sonnet/Opus · 선행: 00

## 1. 왜
- 2026-10-22 확인: `/search`에서 학교 이름을 입력하고 엔터·"학교 검색"을 누르면 "지금은 검색 결과를 불러올 수 없어요"가 뜬다. 자동완성 드롭다운은 정상.
- 원인: `lib/api/search.ts`의 `searchSchools()`가 `search_schools_with_activity` RPC(통계 기록 후 `search_schools_v2` 호출)를 부르는데 Supabase가 400을 반환. 자동완성은 `search_schools_v2`를 직접 불러서 정상. 즉 **통계 기록이 핵심 기능을 죽이고 있다.** 10/14 가입 경로 마이그레이션 이후 `public_account_daily_funnel` 관련 변경과 충돌했을 가능성이 있으나 미확인.

## 2. 작업
1. 재현: `lib/api/search.test.ts`에 "with_activity RPC가 error를 반환해도 결과를 반환한다" 테스트를 먼저 추가(실패 확인).
2. 수정(클라이언트, 필수): `fetchSchoolsBySearchRpc`에서 `recordActivity=true`일 때 `search_schools_with_activity`가 error면 **같은 인자로 `search_schools_v2`를 한 번 더 호출**해 그 결과를 반환한다. 둘 다 실패할 때만 `SCHOOL_SEARCH_UNAVAILABLE`. 통계 실패는 `console.warn` 한 줄(쿼리 문자열은 로그에 넣지 않음).
3. 원인 조사(보고만): 10/14 pull로 들어온 마이그레이션 3개에서 `public_account_daily_funnel`, `increment_public_account_metric`, `search_schools_with_activity`를 건드린 부분을 찾아 보고에 적는다. 추정 원인과 "DB 쪽 수정이 필요하면 새 migration 파일로 어떻게 고칠지"를 제안만 한다. **migration 파일을 쓰더라도 원격 적용은 하지 않는다.**
4. 검증 순서대로. 커밋 `v2-01: school search falls back to search_schools_v2 when activity wrapper fails`.

## 3. 하지 않는 것
- 기존 migration 수정 금지. 원격 DB 접근 금지.
- 검색 UI 변경 없음(03·04번에서).

## 4. 완료 조건
- 새 테스트 통과, 기존 `search.test.ts` 통과.
- 보고에 추정 원인 + DB 수정 제안(있으면 새 migration 파일 경로, 적용은 승인 대기).

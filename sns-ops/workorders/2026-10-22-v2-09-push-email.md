# 작업지시서 v2-09 — 푸시 2종 + 이메일

마스터 규칙 적용 · 예상 4~6시간 · 모델: **Opus 이상** · 선행: 06·08 · 기준 화면: 목업 5·6번

## 1. 왜
- 매일 열 이유는 "누가 새로 들어왔나"다. 지금 열 이유는 "나에게 요청이 왔다"다. 이 둘만 알린다. 그 외 알림은 없다.
- 홈 화면에 추가 안 한 사람(또는 푸시 거부)은 이메일로 같은 내용을 받는다. 없으면 상대가 다시 안 들어와서 수락이 완성되지 않는다.

## 2. 알림 2종 (문구 고정)
| 사건 | 제목 | 본문 | 누르면 |
|---|---|---|---|
| 내 학교·내 졸업연도에 새 멤버십(명단 표시 켜짐) 생성 | `서초고 2005년에 새 동문이 들어왔어요` | `최유진님이 출석부에 등록했어요. 이제 5명이에요.` | `/account` |
| 나에게 인스타 요청 생성 / 내 요청이 수락됨 | `김민수님이 인스타 주소를 요청했어요` / `김민수님이 수락했어요` | `수락하면 서로의 주소가 열려요. 무시해도 상대는 몰라요.` / `이제 서로의 인스타 주소가 보여요.` | `/notifications` |
- 이름은 **받는 사람이 명단에서 볼 수 있는 사람의 이름만**(같은 학교·명단 표시 켜짐). 아니면 이름 없이 `새 동문 1명`.
- 묶음: 새 동문은 1시간 안에 여러 명이면 한 건으로(`새 동문 3명`). 하루 상한: 사람당 새 동문 알림 3건, 요청 알림 제한 없음.
- 23:00~07:00 KST에는 보내지 않고 07:00에 묶어서.

## 3. 푸시 (Web Push, VAPID)
- 구독 저장: **기존 테이블에 컬럼 추가가 불가능하면** 이 작업에 한해 새 테이블 `push_subscriptions_v2`(user_id, endpoint, keys, created_at, last_seen_at) 허용 — 마스터 규칙 5의 유일한 예외. 사용자 데이터가 아니라 기기 토큰이며, 삭제해도 v1에 영향 없음. 보고에 명시.
- 발송 트리거: 멤버십 생성·연결 요청·수락 이벤트에서 서버(API 라우트)가 큐에 넣고, 5분 크론(`/api/cron/notify`)이 묶어서 발송. Vercel 크론 한도 확인(안 되면 기존 reply-helper처럼 Upstash QStash 제안).
- 구독 요청 시점: 설치 안내 화면(08번) 통과 직후 **한 번**, 거부하면 다시 묻지 않음(`/account` 더보기에서 켤 수 있게).
- 환경변수 **이름만** 보고: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`. 값은 운영자가 Vercel 화면에 넣는다.

## 4. 이메일 (Resend)
- Supabase Auth 메일은 인증용이라 이 용도로 못 쓴다. Resend(무료 월 3,000통) 사용. 환경변수 이름 `RESEND_API_KEY`, 발신 `noreply@schoollove.kr`(10번에서 도메인 바뀌면 교체). 운영자가 Resend 가입·도메인 DNS(SPF·DKIM) 등록.
- 템플릿(목업 6번): 제목 = 푸시 제목, 본문 = 학교·연도·이름 + 한 줄 설명 + 버튼 `수락하기`(링크 → `/notifications`) + `무시하기`(아무것도 안 함, 링크 없음) + 꼬리말 `같은 학교 회원이 요청할 때만 보내요. 홈 화면에 추가하면 메일 대신 알림으로 받아요.`
- 발송 규칙: 푸시 구독이 **없거나** 푸시 발송 실패 시에만 이메일. 둘 다 보내지 않는다. 새 동문 이메일은 하루 1통으로 묶음, 요청·수락은 즉시.
- 수신 거부: 꼬리말에 `알림 설정` 링크 → `/account` 더보기 → 이메일 끄기(기존 프로필 설정 컬럼 재사용, 없으면 `v2` 예외 테이블의 플래그).

## 5. 확인
- 단위: 문구 생성(이름 노출 조건), 묶음 규칙, 야간 보류, 하루 상한, 푸시/이메일 택일.
- 통합(운영자와, 3차 후): 계정 2개로 ① 가입 → 상대에게 새 동문 푸시 ② 요청 → 상대 푸시 ③ 상대 푸시 끄고 요청 → 이메일 도착 ④ 수락 → 요청자 푸시. 안드로이드·아이폰 각 1회.
- 검증 순서대로. 커밋 `v2-09: web push (2 events) with email fallback via Resend`.

## 6. 하지 않는 것

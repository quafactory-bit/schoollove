# 작업지시서 v2-06 — 출석부(기수 명단) 화면 + 인스타 요청 한 번

마스터 규칙 적용 · 예상 3~4시간 · 모델: **Opus 이상** · 선행: 03·04·05 · 기준 화면: 목업 4·7번

## 1. 왜
- 포인트는 "기수 전체를 본다"다. 지금은 가입 뒤에도 Lv·XP가 먼저 보이고 명단은 깊숙이 있다. **로그인 후 첫 화면이 출석부**여야 한다.
- 안부 메시지 쓰기는 마찰이다. 버튼 하나(인스타 요청)로 줄인다. 안전장치는 상호 수락 하나로 충분하다.

## 2. 규칙 (화면에 그대로 반영)
1. 명단에 오르면 명단을 본다. 등록 + 명단 표시 켜짐 = 같은 학교 회원의 이름·졸업연도가 보인다. 숨기면 나도 못 본다.
2. 보이는 건 이름 + 졸업연도(+반, 입력한 사람만). 사진·인스타·메시지 없음.
3. 인스타 요청 한 번 → 상대 수락 → 둘 다 서로의 인스타 주소가 보인다. 거절은 조용히(알림 없음).
4. 같은 사람에게 요청은 1회, 취소 후 재요청은 7일 뒤.

## 3. 화면 `/account` (= 내 출석부, 로그인 후 첫 화면)
- 네비: 브랜드마크 · 공유 · 더보기(숨기기·학교 추가·설정)
- `서초고등학교` 회색 / 제목 `2005년 졸업 · 5명`(초록 숫자)
- **새 동문 띠**(`components/NewMembersStrip.tsx`): 연한 초록 박스, `이번 주 새로 들어온 동문 N명` + 아바타 최대 5개(이름, 초록 테두리, N 배지) + `전체 보기 ›`. 최근 7일 기준. 0명이면 띠 대신 `친구 부르기 — 2005년 링크 복사` 버튼만.
- 연도 탭: 내 연도(기본) · ±1년 · 전체. 탭 안에 인원수.
- 명단 행(64px): 아바타 · 이름(+`새로 옴`/`나` 태그) · 소제목(졸업연도 / `나에게 요청함` / `어제`) · 오른쪽 알약 버튼
  - `인스타 요청`(초록) / `요청 보냄`(회색) / `수락하기`(검정) / 나: `숨기기`(글자만)
- 맨 아래: `친구 부르기 — 2005년 링크 복사`(회색 버튼) + 링크 `/school/[slug]/[year]`
- 학교를 여러 개 등록한 사람: 상단에 학교 전환 드롭다운.

## 4. 요청·수락 (기존 connections 재사용)
- "인스타 요청" = 기존 연결 요청 API(`/api/connections`)를 **메시지 없이** 호출. 메시지 컬럼은 null 허용이면 null, 아니면 고정 문구 `출석부에서 인스타 주소를 요청했어요`.
- "수락하기" = 기존 수락 API. 수락 시 기존 인스타 공개 로직(`/api/connections/[id]/instagram`) 그대로.
- 상태 매핑: 기존 상태값 → 버튼 4상태. 기존 상태 enum에 값 추가 금지.
- 기존 `/connections` 페이지는 **알림 탭**(`/notifications`)으로 통합: 상단 `서로 수락한 친구`(인스타 주소 카드, 목업 7번) / `기다리는 중`(요청 보냄·나에게 요청함). `/connections`는 `/notifications`로 리다이렉트.

## 5. 데이터
- 새 테이블·컬럼 없음. "새로 들어온 동문"은 memberships의 생성 시각으로 계산. "최근 본 시각"이 필요하면 **로컬 스토리지**로(서버 저장 안 함).
- 명단 조회 RPC는 기존 roster RPC(9/28 `school_roster_and_direct_discovery`) 재사용. 반환 컬럼을 늘리지 않는다.

## 6. 제거(화면에서만)
- `/account`의 레벨·XP·진행률·`RegistrationGrowthRewardCard`·`SchoolGrowthPanel`·`growth/*` 카드
- `/people/search`(정확한 이름 검색)는 출석부 안의 **이름 필터 입력칸**으로 대체(클라이언트 필터, 기존 `YearPeopleSearch` 로직 재사용). 라우트는 `/account`로 리다이렉트.
- 안부 메시지 작성 화면, `/connections/[id]/messages` UI(라우트는 남기고 링크만 제거)

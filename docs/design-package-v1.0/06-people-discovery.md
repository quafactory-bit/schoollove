# SchoolLoveI Refactoring PRD — People Discovery (Year Hub · Class Hub · Profile) v1.0

Status: **FROZEN**

> **PHASE 10A SAFETY OVERRIDE (2026-07-28):** 공개 Year/Class/Profile 사람 발견 흐름, 이름 검색, 개인 카드와 Instagram 링크를 전면 중단한다. 해당 URL은 개인 행을 조회·렌더링하지 않는 비공개 안내와 noindex/nofollow/noarchive만 제공한다. 사람 발견은 PHASE 10B의 만 19세 이상 본인 인증·소유권·상호 승인 구조 이후 재정의한다.

## 0. 이 문서의 역할

이 문서는 사용자 여정의 뒷단, 즉 **사람을 발견하는 세 화면**(Year Hub · Class Hub · Profile)을 하나의 흐름으로 정의한다.

세 화면은 개별 페이지가 아니라 하나의 발견 여정이므로 PRD도 한 문서로 묶는다.

상위 기준: Product Constitution v1.0, Home Feed PRD, School Hub PRD, Level Policy v3.

---

## 1. 관점 전환 — "학교 서비스"에서 "사람 발견 서비스"로

Home Feed와 School Hub는 **학교의 성장**(레벨·완성도·랭킹)을 다뤘다.

Year Hub부터는 관점이 바뀐다. 여기서 사용자는 실제 사람을 발견한다.

> 사용자의 실제 여정에서 가장 오래 머물고 전환이 일어나는 곳은 학교가 아니라 사람이다.

따라서 이 세 화면은 "학교 페이지의 하위"가 아니라 **스쿨러브아이의 실질적 핵심**으로 설계한다. 성장은 앞단(Home·School)이, 발견은 뒷단(Year·Class·Profile)이 담당한다.

---

## 2. 계층 = 사람 목록을 좁히는 필터

```text
School Hub  →  이 학교의 모든 사람
Year Hub    →  이 기수의 사람          (졸업연도로 필터)
Class Hub   →  이 반의 사람            (반으로 필터 — 가장 좁음)
Profile     →  한 사람                 (필터의 최종 원소)
```

- **Class Hub는 "반 페이지"가 아니다.** 사람 목록을 가장 좁게 필터한 결과다.
- **Profile은 독립 페이지가 아니다.** 필터의 최종 원소인 개인 카드이며, 인스타그램으로 나가는 문이다.
- 반을 아는 사람은 Class로 좁히고, 반을 모르는 사람은 Year 전체 명단에서 이름으로 찾는다.

---

## 3. 프라이버시 경계

| 화면 | 사람 표기 | 이유 |
|---|---|---|
| Home Feed | 익명 | 활동 로그 |
| Year / Class / Profile | 실명(`nickname`) + 공개 인스타 | 명단 페이지 / 서비스 본질 |

- 공개 인스타 계정만 등록 가능하다.
- 무단 등록은 신고·수정·삭제 대상이다.

# Part A — Year Hub

## A0. 정의

Year Hub는 사람 발견의 메인 화면이다.

성장 언어(레벨·랭킹)를 전면에 두지 않는다.

두 축은 **동기 발견**과 **우리 반 찾기**다.

## A1. 화면 우선순위

```text
기수 헤더
  ↓
기수 컨텍스트
  ↓
동기 발견 (Hook)
  ↓
우리 반 찾기 (Navigation)
  ↓
등록 CTA
```

**동기 리스트가 Hook, 반 목록이 Navigation이다.**

## A2. 기수 컨텍스트

P1:

- 가장 활발한 반 — `profiles` 집계
- 최근 등록 — freshness

P2:

- 많이 남겨진 흔적 주제 — `traces` 키워드 추출

## A3. 동기 발견 + 이름 검색 (P1)

- 기수 전체 동기 명단을 Year Hub 안에서 펼친다.
- 각 항목은 이름 + 인스타 + 반 배지.
- 이름 검색은 P1이다.
- 검색은 로드된 명단을 실시간으로 좁힌다.
- 검색 대상은 `nickname`.
- 부분 일치.
- 검색 쿼리를 URL 파라미터로 노출하지 않는다.

"동기 N명 모두 보기"는 Year Hub 안의 전체 명단으로 펼친다.

## A4. 우리 반 찾기

- 반 목록 제공
- 각 반은 Class Hub로 연결
- "우리 반이 여기 없어요 → 반 추가" 진입 제공

## A5. State 3단계

| State | 조건 | 특징 |
|---|---|---|
| 1 빈 기수 | 등록 0 | 첫 기록 중심 |
| 2 성장 기수 | 동기 일부 | 동기 발견 + 반 목록 |
| 3 활발 기수 | 동기 풍성 | 긴 명단 + 이름 검색 + 풍성한 컨텍스트 |

## A6. Year ↔ Class 경계

- Year 전체 명단 + 이름 검색 = 반을 모르는 사람의 목적지
- Class Hub = 반을 아는 사람의 목적지

# Part B — Class Hub

## B0. 정의

Class Hub는 사람 목록을 가장 좁게 필터한 결과다.

화면의 주인공은 반이 아니라 사람이다.

여정의 끝이며 실제 전환(인스타 클릭·등록)이 일어난다.

## B1. 프로필 명단

- 반에 필터된 사람들의 Profile Card 리스트
- 상단: `이 반에 N명이 등록했어요`

## B2. State 2단계

| State | 조건 | 특징 |
|---|---|---|
| 1 빈 반 | 등록 0 | 첫 기록 중심 |
| 2 채워진 반 | 등록 1+ | Profile Card 명단 + 등록 CTA |

빈 반 카피 방향:

```text
3학년 2반은 아직 조용해요.
우리 반의 첫 인스타를 남겨보세요.
```

## B3. SEO

- URL `/{year}/{class}`는 SEO 최종 랜딩
- 프로필 3명 미만 noindex
- 빈 기수/빈 반 sitemap 제외
- SSR 유지

# Part C — Profile Card

## C0. 정의

**독립 Profile 페이지는 없다.**

Profile은 Year/Class 명단의 카드이며 Instagram으로 나가는 문이다.

## C1. 카드 3종

| 유형 | 표시 | 주 액션 |
|---|---|---|
| 인스타 등록 | 이름 + @인스타 | 인스타 보기 |
| 인스타 미등록 | 이름 + 인스타 미등록 | 인스타 추가 |
| 공통 보조 | — | 수정·삭제 / 신고 |

## C2. 액션

### 인스타 보기

Instagram 외부 이동. 발견 여정의 최종 목적지.

### 인스타 추가

로그인 없이 누구나 미등록 카드에 공개 인스타를 추가 요청할 수 있다.

`reports.type = edit`로 저장하고 관리자 확인 흐름을 따른다.

### 수정·삭제

- 인스타 ID 수정
- 이 정보 삭제 요청
- `본인 또는 정당한 관계자입니다` 확인
- 삭제는 관리자 확인

### 신고

사유:

- 잘못된 정보
- 사칭
- 부적절
- 기타

신고 3회 누적 시 자동 hidden.

# Anonymous signup attribution addendum

The operator's 2026-10-14 instruction approves seven-day browser first-touch attribution and four validated UTM parameters for Web Analytics. This narrowly supersedes the no-query/no-client-persistence analytics contract for these fields only. Existing auth/growth exclusions, account consent/ownership and share payloads are unchanged.

First private-profile completion increments only a daily aggregate keyed by KST date and source/medium/campaign/content, treating NULL codes as equal. The sole measure is count; no serial ID, landing path, account identity, email, school, IP, User-Agent, timestamp or full referrer is stored. Browser payloads no longer retain paths. Existing account milestones prevent double counting without adding an attribution identity map. Profile deletion/recreation does not increment; account withdrawal removes the account milestone and leaves anonymous totals unchanged.

The operator approved this follow-up, policy wording, tests and Preview migration. The policy describes a maximum seven-day attribution window and explains removal/refresh on next access because localStorage does not expire automatically. Production release and merge are forbidden for this task. Reassigning preview.schoollove.kr or changing branch environment scopes requires a separate approval after the method and impact report.

The latest operator instruction makes attribution best effort: profile and milestone validation remain mandatory, but optional aggregate errors roll back only that statistics subtransaction and return attribution_recorded=false. Failed statistics are not retried on profile edits, so totals may undercount. Administrator-created synthetic Preview E2E with real sessions and an automation-only protection bypass is authorized; public protection exceptions and real Google OAuth are not. Preview-only noindex headers and robots Disallow:/ are approved, without altering Production SEO or deploying/merging Production.

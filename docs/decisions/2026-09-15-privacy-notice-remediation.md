# 개인정보 수집·이용 및 처리방침 보완

## 승인 범위

2026-09-15 사용자의 “1,2,3 모두 처리하자” 요청에 따라 가입 시 수집·이용 고지,
개인정보처리방침 필수 기재사항, 처리위탁·국외 이전 고지를 보완한다.
기존 개인정보 공개 범위, Google-only 인증, 필수 동의 네 항목과 선택 입력은 유지한다.
배포·원격 DB mutation·계약 체결·외부 메시지 발송 승인은 포함하지 않는다.

### 2026-09-16 후속 승인

사용자의 “응 승인할게”는 직전 보고의 개인정보 고지 배포에 대한 승인으로 기록한다.
고지 내용이 확정되면 필요한 commit/push/merge와 운영 배포를 같은 승인 범위에서 진행하며
같은 배포 승인을 다시 요청하지 않는다. 원격 DB mutation·계약 체결·외부 메시지 발송·
새 개인정보 기능 활성화는 이번 고지 배포에 포함하지 않는다.
승인은 미확인된 운영 사실의 증명이 아니므로 ‘확인 중’ 초안을 최종 방침으로 배포하지 않는다.

## 구현 원칙

- 동의 전에 목적, 필수/선택 수집 항목, 보유기간, 동의 거부권과 불이익을 읽을 수 있게 한다.
- 같은 수집 고지를 계정 화면과 처리방침에서 공유해 내용이 어긋나지 않게 한다.
- 서비스 이용에 필요한 Google 인증과 복구 절차는 해당 입력 전에 안내한다.
- 공급자 법인명, 연락처, 처리 업무, 국가, 이전 시기·방법, 보유기간, 거부 방법·효과를 구분한다.
- 주 DB 지역과 사업자 본사 소재지, 발송 지역과 실제 저장 지역은 혼동하지 않는다.
- 공개된 공급자 기본 정책은 실제 계약·프로젝트 설정의 증명이 아니다.
- 검증되지 않은 담당자, 요금제, 데이터 위치, 파기 기한을 만들어 쓰지 않는다.
- 고지 개정은 과거 동의의 소급 보완이나 모든 법적 요건 충족을 뜻하지 않는다.
  기존 동의 기록/성인확인 authority와 정책 버전을 임의로 변경하지 않는다.
- 이번 고지의 최종 공개 전 운영 정보와 기존 동의에 대한 재동의 필요성을 확인한다.

## 확인된 운영 근거

- Supabase 프로젝트 목록: 기존 운영 문서에서 지정한 `schoollovei`의 주 DB는
  `ap-southeast-1`(싱가포르). Preview는 별개이며 운영 고지에 섞지 않는다.
- Vercel 팀·배포 조회: 현재 Hobby. 프로젝트 이름 `schoollove-kr`, 운영 함수 지역 `iad1`(미국).
- 보호책임자 성명·기존 이메일·전화는 사용자가 제공했으며 최종 전화는 업무용 번호로 변경했다.
- 운영 DB 함수 정의만 SELECT하여 탈퇴 시 복구 이메일 암호문 제거,
  복구 HMAC/registry 잔존, 삭제 완료 기록의 90일 purge 기한을 확인했다.
  개인 행·환경변수·비밀값은 조회하지 않았다.
- Resend 공식 GDPR 안내: 고객 데이터 저장은 미국. Free/Pro/Scale 이메일·로그 30일,
  백업 7일. 실제 계정 요금제 확인 전 해당 기한을 확정 운영값으로 쓰지 않는다.
- 2026-09-16 Supabase get_project/get_organization 조회: 운영 `schoollovei`가 속한
  `schoollove` 조직의 요금제는 Free. 공식 가격표의 API/DB 로그 보관은 1일이며,
  유료 플랜의 7일/14일/30일 백업 정책을 운영 Free 계정에 적용하지 않는다.
  수동 외부 백업이나 별도 지원 접근의 존재 여부는 이 메타데이터로 확인되지 않는다.
- 같은 날 Upstash는 로그인 화면, Resend 설정 접근은 비로그인 홈페이지,
  Supabase 백업 화면은 로그인 화면으로 연결됐다. 자격증명 입력이나 로그인 승인은 실행하지 않았다.

### 모바일 화면으로 확인한 운영 정보

- 사용자 제공 Resend Billing 화면의 Transactional 3,000 emails / $0 표시로 Free 요금제를 확인했다.
  공식 Free 정책인 이메일·로그 30일, 백업 7일을 고지에 반영한다.
  공식 GDPR 안내는 모든 계정에 가입 시 DPA가 적용된다고 명시하며 별도 서명을 요구하지 않는다.
- 사용자 제공 `schoollove-ratelimit` 상세 화면과 확대 화면에서 AWS, Free Tier,
  Tokyo/Japan `ap-northeast-1`, Global을 확인했다. 확인된 저장 지역은 일본 도쿄로 반영한다.
  Global은 서비스 유형이며 여러 국가 저장의 증명으로 쓰지 않는다. 추가 Read Regions의 유무와
  로그/백업의 별도 보관 조건은 이번 상단 화면만으로 확정하지 않는다.
- 원본 모바일 사진의 청구 연락처, 연결 문자열, 결제 관련 정보는 공개 문서에 복사하지 않는다.

## 최종 공개에 필요한 사실

후속 승인: [2026-09-16 삭제 기준과 배포 결정](2026-09-16-privacy-retention-release.md)에 따라
확인된 고지·삭제 기능의 배포와 공급자의 미확정 계약·보관 범위를 구분한다.
아래 목록은 이전 초안의 미확정 사항이며, 현재 구현·배포 상태는 후속 검증 보고서를 따른다.

1. 개인정보 보호책임자 성명과 공개 연락처: 사용자 확인 완료.
2. Upstash의 도쿄 지역·AWS·무료 티어는 확인 완료. 추가 읽기 복제 지역, 백업 및 보안 로그 보유기간은 미확정.
3. Vercel 함수·로그·Analytics의 실제 처리 지역과 보관 범위; 조회 가능 기간을 전체 삭제기한으로 해석하지 않는다.
4. Resend Free 요금제와 표준 보관·DPA 조건은 확인 완료. Supabase 백업 정책과 공급자별 재위탁의 적용 범위는 미확정.
5. 탈퇴 후 남는 recovery HMAC, broker subject, cleanup job 등의 보유 목적·기한과 실제 파기 경로.
6. 기존 동의와 신구 고지 차이를 확인하고 필요한 경우 별도 동의 기록 전환을 설계한다.

이 항목들이 해결되기 전 상태는 고지 보완 작업 중이며, 배포 가능 또는 법적 정비 완료로 표시하지 않는다.

## 2026-09-16 추가 근거 검토와 삭제 기준안

- [삭제 기준 제안서](../proposals/2026-09-16-privacy-retention-and-deletion.md)에 공급자별 확정 사실,
  미확정 계약·보관 범위, 현재 삭제 경로와 구체적인 보완안을 정리했다. 정책 채택·구현 완료 기록은 아니다.
- 운영 함수 정의를 읽기 전용으로 확인했다. 탈퇴 완료 뒤 recovery HMAC, 로그인 식별자,
  완료 작업의 Auth UUID를 정리하는 보완이 필요하다. 90일 감사 파기 함수는 존재하지만
  현재 저장소의 일일 작업에는 연결되지 않았고 운영 pg_cron도 설치되지 않았다.
  저장소 밖 수동 실행·자동화의 존재까지 배제하지 않는다.
- 권장안은 직접 개인정보의 지체 없는 삭제(정상 완료 목표 24시간), 인증 종료 후 잔존 식별자 정리,
  OTP 만료 후 5분 이내 정리 목표, 24시간 발송 제한 이력의 별도 파기,
  개인과 연결할 수 없는 운영 통계만 최대 90일 보관이다. 이 시간들은 법정 유예기간이 아니다.
- 자발적 탈퇴 후 새 인증·동의로 재가입을 허용하는 안은 제품 결정으로 제안만 했다.
  기존 제재·신고 보호와 실패한 삭제 작업을 임의로 제거하지 않는다.
- 현재 [Vercel 공개 DPA](https://vercel.com/legal/dpa)는 Pro·Enterprise를 대상으로 하므로
  Hobby 적용 처리계약을 확인해야 한다. Resend Free의 표준 조건은 확인 완료이며,
  Upstash·Supabase의 내부 로그·백업 범위 등 공개 자료의 한계는 문의 초안에 구체화했다.
- 기존 고지 배포 승인은 유지한다. 공급자 문의 발송, 유료 변경, 새 정책 채택 및 실제 DB 파기는
  실행하지 않았다. 제한적 연락처 정정과 전체 고지 완성을 구분하며 이번에는 배포하지 않았다.

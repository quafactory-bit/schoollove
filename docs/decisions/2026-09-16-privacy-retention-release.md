# 개인정보 삭제 기준 채택과 배포 승인

사용자 승인: “응 진행해서 배포까지 완성해줘”. 2026-09-16.

이 결정은 전날 제안한 보관·삭제 기준의 구현, 검증, 필요한 새 migration의 운영 적용과
이번 개인정보 고지의 commit/push/merge/Production 배포를 승인한 것으로 기록한다.
기존의 다른 기능·베타 활성화와 계정 공개 상태 변경, 유료 계약 변경은 포함하지 않는다.

## 채택 기준

- 직접 개인정보는 검증된 본인 탈퇴 처리에서 지체 없이 삭제하며 정상 완료 목표는 24시간이다.
  24시간은 삭제 대기기간이나 법정 유예기간이 아니다.
- Auth 실제 삭제가 확인된 자발적 탈퇴에 한해 개인 계정·로그인 식별자·완료된 삭제 작업을 정리한다.
  로그인 시도와 발급 토큰의 재사용 방지를 위해 완료 후 15분의 짧은 정리 대기 창을 두고
  5분 주기 작업으로 제거한다. 실제 Auth가 남아 있거나 실패·제재 보호가 필요한 작업은 임의 삭제하지 않는다.
- OTP 비밀재료는 사용·취소 즉시, 미사용은 만료 후 5분 주기 정리한다.
  발송 제한 HMAC은 예약 시각으로부터 24시간만 유지하며 계정 삭제와 별도로 만료시킨다.
  계정 참조를 먼저 제거하더라도 24시간 제한을 우회할 수 없게 한다.
- 개인 요청·작업 ID를 남긴 90일 기록 대신 날짜별 완료 건수만 최대 90일 보존한다.
  학교·사람·성장 통계와 결합하지 않는다. 기존 신고·차단 데이터는 이 정리 작업의 대상이 아니다.
- 삭제 완료 후 재가입은 새 인증·새 동의·새 계정으로 시작한다. 이전 관계·동의를 복구하지 않는다.
- 백업·공급자 내부 로그는 확인된 범위만 고지한다. 미확정 기간을 추정하거나 법적 정비가
  모두 완료됐다고 선언하지 않는다. 공급자 문의 초안 발송과 유료 전환은 이번에 실행하지 않는다.

## 구현 경계

- 적용된 migration은 보존한다. 새 정리 함수는 service_role 및 DB 예약 실행만 허용한다.
- DB pg_cron의 5분 주기 실행과 결과 기록을 검증한다. 앱의 기존 운영 작업도 보조 호출한다.
- 정리는 한 실행의 건수를 제한하고 잠금 충돌 시 다음 실행에서 재시도한다.
- 실제 이용자 행은 로컬 복사하지 않는다. schema-only 복제와 합성 데이터로 삭제·실패·권한을 검증한다.
- DB 삭제가 성공했으나 앱 응답이 끊긴 경우 다시 처리할 수 있도록 기존 2단계 절차를 보완한다.
- 공개 고지는 이번 시행일과 확인된 사실을 사용한다. 과거 동의 버전은 재작성하지 않는다.

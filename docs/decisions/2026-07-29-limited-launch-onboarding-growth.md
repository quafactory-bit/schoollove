# PHASE 10H 제한 출시·온보딩·성장 운영 결정

## 결정

PHASE 10H는 공개 가입 전환이 아니다. 이메일 OTP로 로그인한 만 19세 이상 사용자 가운데 필수 동의를 완료하고, 해시 기반 제한 베타 초대를 사용한 뒤 운영자 승인을 받은 사용자만 개인 기능에 접근한다.

온보딩 순서는 다음으로 고정한다.

1. 이메일 OTP 로그인
2. KST 기준 만 19세 이상 자기진술
3. 필수 동의
4. 해시 초대 사용
5. 운영자 승인
6. 기본 비공개 본인 프로필
7. 과거 졸업연도의 본인 학교 이력
8. exact match 사람 찾기 준비 완료

## 개인정보·성장 측정 경계

- 온보딩 진행 상태는 본인과 service role만 읽을 수 있다.
- 초대 원문, 이메일, 이름, Instagram, 학교명, 검색어, IP, referrer, raw UTM은 성장 지표에 저장하지 않는다.
- 유입 출처는 `direct`, `organic_social`, `creator`, `community`, `referral`, `paid_social`, `unknown`의 거친 분류만 허용한다.
- 운영 화면은 현재 단계별 인원과 날짜·출처·단계별 집계만 표시한다.
- 단계·날짜·출처 세그먼트가 10명 미만이면 정확한 수를 반환하거나 표시하지 않는다.
- 분석 화면은 개인 drill-down을 제공하지 않는다.
- 단계 진입 집계는 같은 사용자의 같은 단계에 대해 최초 한 번만 기록한다.
- 계정 삭제 시 사용자 연결 온보딩 상태와 단계 이벤트는 cascade 삭제한다. 익명 집계는 승인된 보존 정책 기간만 유지한다.

## 출시·결제 경계

- 공개 초대 링크 공유와 불특정 다수 가입 유도는 계속 금지한다.
- 같은 사용자의 같은 프로그램 초대 재사용은 사용 횟수를 다시 소비하지 않고 차단한다.
- 사용자의 membership이 있는 프로그램을 온보딩 기준으로 우선하며 다른 active 프로그램과 섞지 않는다.
- `people_search` 중단은 새 안부 생성·재알림·응답까지 연쇄 차단하고, `messaging` 중단은 기존 연결의 대화 읽기·쓰기까지 차단한다.
- 신고·차단·연결 해제 같은 안전 조치는 기능 중단 중에도 허용한다.
- 기존 공개 프로필 25건에 소유권을 부여하거나 수정하지 않는다.
- PHASE 10G 결제 Provider는 `manual` 또는 `disabled`로 유지한다.
- PHASE 10H migration과 PR은 별도 승인 전 Production에 적용하거나 merge하지 않는다.

## 운영 실패 원칙

- 온보딩 단계 동기화나 집계 기록 실패가 본인 프로필 저장 등 핵심 요청을 되돌리지는 않는다.
- 관리자 운영 화면과 API는 기존 관리자 세션을 계속 요구한다.
- 개인정보 원문을 로그나 운영 응답에 추가하지 않는다.
